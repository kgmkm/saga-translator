# 中国語 → 日本語 翻訳tips

`src=zh` の方向（zh→ja）のとき読む。機械側は `scripts/lang/zh.py`。
v1 で品質を保証するのはこの言語だけ。簡体・繁体は `han_script` を見る。

## 役割

あなたは中国語 Web 小説の日本語翻訳者である。次の制約で【対象本文】を翻訳し、結果を段落番号付きで出力せよ。

## 原語の扱い

- 登場人物表の漢字名を訳文に残さない。残ったら leftover_source_names QA の不合格
- 文脈上どうしても原語が必要なときだけ、訳語のあとに原語を併記する
- 你/您、们 は `first_person` / `second_person` / `address` に反映する。字面を残さない

## 固有名詞

- 意味が明確なら日本語に置く
- 字面を生かす漢語は音訳+ルビ。初出だけ `{訳語|よみ}`(VFM)
- 未登録なら、そのブロックの翻訳より先に用語集/人物表へ1つ決めて登録する
- JIS に載っていても日本人に読めない字（筱 等）を人名の訳語に使わない。読める字で組む

## ジャンル別命名慣行（魔法少女・ヒーロー・戦闘美少女など）

- **コードネーム（原文の「代号」）・変身名は、日本語のカタカナ英語（和製英語を含む）にする。** このジャンルのコードネームは英語圏の語から作られるのが通例で、漢語の字面を残すと日本語圏の読者には通らない（例: セーラームーン / プリキュア / まどか☆マギカ。「猩红」→スカーレット、「银月」→シルバームーン）
- **漢語の字面を生かすのは人名**（姓・名）。人名は上の「固有名詞」節どおり、字面＋初出ルビ（`{訳語|よみ}`。初出だけ）
- 人名とコードネームは**分けて判定する**。人名の [naming_policy].style はコードネームには適用しない
- **コードネームにはルビを振らない**（カタカナで読みが自明。振ると後でカタカナ化するとき VFM を外す手間が出る）
- 機械側の候補抽出は `lock_prep.py` の「コードネーム候補」節（「代号」の明示抽出。頻度・長さの足切りなし）。判定を固定したら house_style.toml に登録する:
  - 既定の宣言: `[naming_policy]` の `codename = "katakana" | "sinitic" | "keep"`（katakana=カタカナ英語。人名の style とは別キー）
  - 個別ルール: `[[rules]]` に `kind = "naming"` で書く（`scope = "series"` は連作で共有。例）:

```toml
[[rules]]
id = "codename_katakana_en"
kind = "naming"
scope = "series"
target = "<シリーズID>"
pattern = "代号"
preference = "コードネームはカタカナ英語にする（例: セーラームーン式）"
rationale = "魔法少女もののジャンル慣行"
status = "approved"
version = 1
```

## 章・形式

原文の章見出し例: `第X章` / `序章` / `楔子` / `番外` / `终章`。分割は scripts がやる。訳文の見出しは日本語として自然な形でよい（「第N章」）。

## 文体

- 漢語の直置き過多を避ける。読み上げて自然な日本語にする
- 擬音・身体反応は字面の直写より、日本語で実感のある表現へ
- 原文の冗長は情報を消さずに残す

## 年齢の手がかり（zh）

年齢・学年を本文が直接書いていることがある。分析の要約だけで判断しない。

- 検索例: `岁|歲|年生|看起来只有|十五|十六|十七`
- 年齢を統一するなら、本文の該当文も置換対象になることをユーザーに明示する

## 中国語由来の落とし穴

### 誤字と設定揺れを分ける

| 種別 | 扱い |
|---|---|
| 明らかな誤字（同音・字形混同など） | 正字に直して訳す。原文ファイルは触らない。人物表・terms は正字で登録 |
| 設定・変身ものでの髪色・瞳色・姓の揺れ | 意図的変化の可能性がある。矛盾として「修正」しない。原文の記述に従う |
| 日本語に無い字 | 常に正字・読める字へ。上記どちらでも訳文に残さない |

誤字に気づいても `[要確認: …]` を本文に残さない。作業後にユーザーへ確認を取る。

### 読めない漢字・非JIS

- 機械: `qa_translation` の `non_jis_han` が CP932 外 + `scripts/lang/zh.py` の `NON_JIS_HAN` を検出する
- 新しい読めない字に当たったら `NON_JIS_HAN` に追記する

### 簡体字の書き残し

訳文ドラフトには簡体の書き残しが出る。`qa_translation.py --emit` の前に:

```bash
python3 scripts/normalize/zh2ja.py <draft>
```

opencc と手当て表で大半が直る。未解決だけ手で見る。一括は `--all <work_id>`、検出のみは `--check`。

### 完成後の再走査

ブロック確定時に加えて、assemble 後に訳文全体を再走査する。rename_terms 後などでも残渣が混入しうる。

- 対象: `output/` 配下の `*_ja.md`（`_lib.find_non_jis_han`）
- 原文 (`chapters/`・`originals/`) は対象外
- 検出したら `rename_terms.py` で伝播するか、該当ブロックを再翻訳

### 字は通るが語としては中文

`non_jis_han` が見るのは字体だけ。一字一字が日本語にあっても、語としては中文のまま残ることがある（例: 凌頂・眸光・一截）。

- 確定後・assemble 後に、既知の残留パターンと「既存訳に無い漢語」を grep する
- 作品の `terms.toml` に無い語は疑う
- 成人向け作品の既知リストは拡張スキル（`saga-translator-spicy`）に譲る。本文ファイルでは扱わない

### TOMLに簡体を残さない

説明文・memo は訳語（日本語表記）で書く。簡体が残ると次回の context 生成で原文と混同する。
