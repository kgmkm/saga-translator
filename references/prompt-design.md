# プロンプト設計

prompt_version: v3（このファイルの版を record_meta.py に渡す）

コンテキスト（`translation_input/chXXX_bY_translation.md`）だけを入力とし、出力は規定の形式に限定する。

原語固有の規則は `references/lang_{lang}.md` があればそちらを優先する。無ければ下記の汎用制約だけ使う。

## 翻訳プロンプト（各ブロックで実行する指示全文）

```
あなたは小説の日本語翻訳者である。原語はコンテキストの言語判定に従う。次の制約で【対象本文】を翻訳し、結果を段落番号付きで出力せよ。

【形式】
- 段落は `[P###]` で始める。追加・削除・結合・分割をしない（1段落＝1段落）
- 出力は訳文のみ。解説・注釈・原文の複写を入れない
- 画像: `![](images/…)` と未解決の `[uploadedimage:数字]` はそのまま残す。訳さない。段落から消さない
- 台詞は鉤括弧 `「」` で書く。原語の `“ ”` を訳文に残さない
- 行の並びは原文に従い、セリフは独立した行にする。行間の整形は qa_translation.py --emit が行う

【訳語と声】
- 【登場人物表】の訳語を厳守
- 一人称は `first_person`、二人称は address があればその `form`、なければ `second_person`
- 口調は `speech_style` の語尾実例に合わせる。別キャラの語尾を混ぜない
- 語彙は `vocab` に従う（漢語・擬音・俗語の可否）
- 口癖は `catchphrase`。印として残すが連発しない
- 声の変化は【語調の変化】の arcs に従う。対象ブロック以降に効く arc の一人称・口調・語彙を使い、節目より前の語尾に戻さない
- 旧ファイルに `tone` しか無いときはそれを代用にする。新規は `tone` に混ぜない
- 【用語集】の訳語を厳守。未登録の固有名詞は、意味が明確なら日本語に置き、そうでなければ用語集に登録してから使う。音訳・ルビ規則は lang_*.md
- 人名・固有名詞のルビは初出のみ。2回目以降はルビなし
- 地の文は常体
- 原語を残すかは lang_*.md。指定が無ければ人物表の訳語に置き、原語は残さない

【文体】
- 対象は日本のWeb小説/ラノベの読者。訳し言葉(「〜であったり、〜であったり」の乱用)を避け、読み上げて自然な日本語にする
- 感情表現・身体反応・擬音は直訳せず、日本語の実感に合う表現に置き換える
- 原文の段落に明示されていない情報を補ってはいけない。代償として不明な点は `[要確認: …]` を本文に残さず作業後にユーザーへ確認を取る。
- 原文の言い回しが冗長でも、情報を消さない。削るより残す

【文脈】
- 【前章末尾の訳文】の文脈を受けて自然に接続する
- 【次章冒頭】は前後関係の把握用。内容を訳文に漏らさない

【対象本文】
(コンテキストファイルの対象本文部分をそのまま貼る)
```

※実際の運用では、コンテキストファイル丸ごとをエージェントが読み、上記の制約が SKILL.md から効いている形になる。エージェントへの追加指示はこのファイルに書いて参照させる。

## 分析プロンプト（ローリング分析の各ブロックで実行）

```
【前作の分析】が与えられている場合、そこに載っている人物の訳語・first_person・second_person・address・speech_style・vocab は確定値として扱い、書き換えない。carry_analysis.py で引き継いだ値は前作終了時点の状態（前作の arcs を畳み込み済み）なので、現作の第1ブロックからその声を使う。変化があれば arcs に追記する。別の訳語にしたいときは proposed に記す。新規の人物・用語も前作の表記（敬称・ルビ形式・呼び方）に合わせる。

【対象本文】を読み、翻訳に必要な次の情報だけを抽出する:

1. 登場人物: このブロックに登場した、作品通して使い続ける名前。通行人は原語・訳語・役割だけ。セリフがある人物は声の欄を分けて書く（混ぜない）:
   - first_person / second_person
   - address: このブロックで呼びかけた相手ごとの呼び方 `{target_src, target_ja, form}`
   - speech_style: 敬語かタメ口か、と語尾の実例を2〜4個。形容詞（丁寧・元気）だけで済ませない
   - vocab: 語彙の特徴（1文）
   - catchphrase: 口癖。なければ空
   - 外見（1文）・関係性の要約（1文）
   既に【登場人物表】にある人物は訳語を変更しない。候補が異なるときは proposed に記す。声の欄が空ならこのブロックで埋める
2. キャラの変化: 精神状態・一人称・口調・語彙・呼び方が変わった人物は arcs に追記する（at_block に起点）。変わった欄だけ書く。精神状態は note、声は speech_style / first_person 等。既存 arcs と矛盾しない。過渡期は note に「混在（表と裏）」
3. 用語: 武功・技・組織・魔法・システム等の固有名詞。原語・訳語・読み・メモ。初出の訳を決める。既に【用語集】にある用語は変更しない
4. あらすじ: このブロックで起きた出来事を3行以内で plot-[ネタバレあり].toml に追記する（ネタバレを含む）。あらすじ・注記は日本語で書く。原文の語彙・表現（一人称・呼称・固有名詞の原語）を括弧書きで残さない。訳語で書く
5. タイトル: このブロックが作品の最後なら、原題とこれまでのあらすじから日本語タイトルを1つ決めて analysis/titles.toml に書く。章見出し（src→ja）も同じファイル。直訳で死ぬ題は意訳してよい。候補が割れるときだけ note に残す。既にあれば上書きしない（ユーザー修正を守る）

登場人物の追記先は `characters-[ネタバレあり].toml`。JSONは書かない。

出力は TOML の追記分のみ(コードブロック)。説明文を書かない。
```

※分析成果物のスキーマは `data-schema.md` を参照。既存訳語は勝手に変えない。

## QA修正プロンプト（qa_translation.py が FAIL を返したとき）

```
qa_translation.py の指摘を修正し、同じ形式で再出力せよ:
- paragraph_sequence FAIL: 段落番号が期待範囲（P###〜P###）と一致するよう出し直す。段落を結合・分割して合わせるのではなく、原文の段落構成を保ったまま番号を振り直す
- empty_paragraphs FAIL: 空段落には最小限の訳（擬音・短い描写）を入れる
- leftover_source_names FAIL: 指摘された原語名を人物表の訳語に置換する。原語を残してよい条件は lang_*.md に従う。指定が無ければ残さない
- non_jis_han FAIL: 指摘された漢字は日本語に無い字（簡体字・原文の誤字・未登録の固有名詞）。日本語の正字に置き換えるか、固有名詞なら人物表/用語集に登録した訳語に置換する。原文の誤字を原文ママで訳出してはならない（誤字は正しい字に直す。悪堕ちの身体変化ルールは誤字の温存を意味しない）
```

## 出力スタイル参考（SOUL）

- 地の文は常体。評価語（「美しい」「素晴らしい」）の乱用を避け、感覚の具体で表す
- 段落は短く。原文が長くても情報を消さない
- フィラー（「〜に他ならない」「心の奥底で」）は使わない
- セリフの文末詞・口癖は人物表に固定する。会話文の印象が章をまたいで変わらないこと
