# P0-3 例外設計: 残渣検出の許容・除外・誤検知対策

## 1. 許容される訳語に原語と同じ漢字が含まれる場合

意図的に原語（中国語）と同じ漢字表記を既定訳として使うことがある。
これらの語は字形検査・語彙検査を素通りさせる必要がある。

- **管理方法**: `house_style.toml` の `known_terms` フィールド。
  作品単位で管理し、`ResidueConfig.known_terms` に渡す。
- 例: 「データ奪舍」（簡体字「夺」は CP932 外だが意図的な用語）

## 2. 引用・固有名・同形異義語

- **原文ブロック**（対訳ファイルの `>` 行）: 原文そのものなので検査対象外。
  `find_zh_vocab` は `>` で始まる行をスキップする。
- **`*_src` キーの値**: `name_src` / `term_src` / `target_src` / `title_src` / `src`
  は原文を保持するのが仕様なので、TOML 検査でも日本語テキスト検査でも除外する。
- **age_policy_report**: 機械生成・原文引用を含む正当な記録なので、ファイル名に
  `age_policy_report` を含むファイルは `find_cn_residue_toml` の対象外。
- **同形異義語**（日中共通の漢字だが意味が異なる）: 現在の辞書には含めない。
  検出が「候補」であることを利用し、人間が判断する。

## 3. ja→zh で日本語 memo が正当な場合

中国語訳に日本語の memo や注釈を残す業務フローがある場合、
それらは検出対象から除外する。

- **現状の判断**: 検出はあくまで「候補」。全ての仮名・鉤括弧を自動置換する
  ものではない。人間が確認して残す判断を尊重する。
- **今後の拡張**: 必要に応じて `ResidueConfig.allow` に特定のパターン
  （`TODO`、`FIXME`、レビュー用マーカーなど）を追加する。

## 4. 誤検知許容（SNS・Day・M）は ResidueConfig.allow に置く

日本語でも使われる英単語・記号・略語は誤検知の原因となる。

- **allow 辞書** (`zh2ja_residue.toml` の `[allow]` セクション):
  これらのワードが文中に現れても検出から除外する。
- 現状の登録語: `SNS`, `Day`, `M`
- **拡張方法**: 作品特有の許容語は呼び出し側で `ResidueConfig.allow` に追加する。
  汎用的なものは `zh2ja_residue.toml` の `[allow]` に追加してよい。

## 5. 検出は「候補」であって自動置換しない

- `safe_fix` は文脈非依存で安全な置換先を **提案** するだけ。
- 特に **成語（idiom）** の置換は接続が不自然になりやすい。
  `safe_fix` をそのまま適用せず、前後を確認して手動で調整する。
- 現状の P0-3 では検出のみ行い、QA への接続（emit の必須条件化）は
  次のフェーズで行う。

## 6. 簡体字の誤検出対策（JP_OK）

一部の簡体字文字は日本語新字体と字形が一致するため、検出から除外する。

- 除外リスト `JP_OK`: `沉着震荡捨無張見開現据結社対応戦涙間問門魚鳥馬車東書様誰話説発尽図団羅蘭銅鐵`
- このリストは `check_zh_vocab.py` から引き継いだ値。拡張する場合は
  `zh2ja.py` の `find_zh_vocab` 関数内の `jp_ok` 変数を編集する。

## 7. 作品固有語の扱い

- 作品固有の人名・固有名詞（张三・李四・王五 等）は
  **汎用辞書 `zh2ja_residue.toml` には入れない**。
- `ResidueConfig.known_terms` 経由で渡すか、または
  将来の `house_style.toml` 統合時に作品固有の設定として保持する。
